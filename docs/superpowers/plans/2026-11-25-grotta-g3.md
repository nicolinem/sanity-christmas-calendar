# Grotta: G3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Etasje 1–5 blir et ferdig spill:
- rom med ulik karakter (rolig, vanlig, reir);
- monstre som våkner bare i ditt rom;
- flaggermus;
- «full etasje» der trapperommet er sperret;
- Isvetten og kista med rustning på etasje 5;
- det som må være på plass før flagget slås på.

**Architecture:**
- Ren data og regler først. Rom-typer, trapperom og rom-indeks per monster kommer fra generatoren (`generate.ts`, `layout.ts`). Sjefer og kister er fakta i `Progress` (`bosses`, `chests`). XP og utstyr regnes ut av fakta (`xp.ts`, `wardrobe.ts`).
- Scenen bruker dataene, og HUD-en viser sjefens liv, sperret trapp og nytt nivå.

**Tech Stack:** Phaser 4.2.1, React 19 / Next 16, TypeScript, `node --test` med `sucrase`.

**Spec:** `docs/plan-grotta.md`:
- del 13, «G3: beslutninger»;
- del 4–8 (rest floors, kamp, data);
- del 12 (store etasjer).

Bygger på grenen `claude/grotta-stemning`.

## Global Constraints

- Alt står bak `FEATURES.cave`. Med flagget av er bygda nøyaktig som før.
- Nye felt i `Progress` legges bare til og vaskes i `readProgress`. XP og utstyr fra sjefer og kister regnes ut av fakta. Bare monster-XP lagres (`Progress.xp`).
- Alle tall er startverdier og står som navngitte konstanter.
- Norsk tekst er nøyaktig som skrevet her:
  - «Trappa er stengt. Slå monstrene i rommet først.»
  - «Isvetten»
  - toast etter kista: `{ title: "Rustning", body: "Du fant den i kista på etasje 5." }`
  - nytt nivå: `{ title: "Nivå N", body: "Våpnene dine gjør nå X skade." }`
- Grotta står stille når Studio er åpent eller vinduet er i bakgrunnen, som i G2. Ingen luke leser noe fra grotta.
- Bare Kenney-ark i repoet. Ingen nye avhengigheter.
- Kjør `npx prettier --write` på endrede filer. Commit aldri `.claude/launch.json` eller `docs/presentasjon/`.

## Review Focus

1. **Sjef og kiste én gang:** etter at Isvetten er slått, kommer den aldri tilbake, og kista gir rustningen bare én gang, også etter reload eller besvimelse. Testes i task 1 og task 4.
2. **Sperret trapp kan alltid åpnes:** et trapperom som er sperret, har minst ett monster som scenen faktisk tegner. Bare `PLAYABLE` regnes. Er det null, er rommet ikke sperret. Testes i task 2.
3. **Reload på hvileplassen:** `trip` er allerede trygt der. Det dobles ikke, og det mistes ikke. Testes i task 1.
4. **Gamle lagringer:** `bosses` og `chests` som mangler eller er ugyldige, blir `{}`. Testes i task 1.
5. **Nivå-feiring dobles ikke:** en luke som gir nytt nivå, viser fortsatt bare lukens feiring, ikke i tillegg en toast. Testes i task 5.

- **`Progress` gains** `bosses: Record<string, true>` and `chests: Record<string, true>`. Both default to `{}` and are washed like `found`.

- **`ownedGear`** adds `armour:plate` when `chests["cave-5"]`.
- **The plate's `unlock` label** becomes `"Kista på etasje 5"`.

### Task 2: Rom-typer, trapperom og rom per monster

**Files:** `src/game/cave/layout.ts`, `generate.ts`, `enemies.ts`, `brain.ts`, with tests in `generate.test.cjs`, `layout.test.cjs` and `brain.test.cjs`.

**Interfaces:**
- **`roomAt(x, y, layout): number`** takes px and returns the row-major room index, clamped to the layout.
- **`type RoomKind = "start" | "calm" | "normal" | "nest"`**, and `Floor` gains `kinds: RoomKind[]`.
  - Every room except room 0 rolls: calm `< 0.25`, nest `< 0.40` (only when `depth ≥ 2` and there is no nest yet), otherwise normal.
  - Rest floors are `["start"]`.
- **Monsters per kind:**
  - calm: `r() < 0.5 ? 0 : 1`;
  - normal: as today;
  - nest: `4 + (r() < 0.5 ? 0 : 1)`, capped by the room's `m` count;
  - the floor total stays capped at 10.
- **Rocks:** calm rooms keep every `o`. Other rooms keep 60 %.
- **`spawns`** gets `room: number`.
- **`Floor.stairsRoom: number`.**
- **`Floor.locked`:** about 1 in 4, never on depth 1 or a rest floor, and only when the stairs room has at least one spawn whose kind is in `PLAYABLE`. It means the stairs room is locked.
- **Nest cache:** `Floor.cache?: { id: string; x: number; y: number; items: { item: MaterialId; count: number }[] }`.
  - It sits in the nest room, on a `.` tile at least 3 tiles from every wall and spawn. If there is none, there is no cache.
  - It holds 2–3 items, each `malm` or `isskar` at 50/50.
  - The id is `nest-${depth}-${seed}`. It is not saved; it belongs to this trip.
- **`PLAYABLE`** gets `"bat"`. Bats are `flies: true` in `ENEMIES`.
- **`stepBrain(b, player, now, dt, move, canWake = true)`:** an idle brain only wakes when `canWake` is true.

- [ ] **Step 1: Write the failing tests:**
  - `roomAt`;
  - over 1000 seeds × depth 2–9:
    - room 0 is always `"start"`;
    - there is at most one nest;
    - calm rooms have ≤ 1 monster and nests have ≥ 4 when they have the spots;
    - every spawn has a correct `room`.
  - `locked` is never true on depth 1 or 5, and the stairs room then has at least one `PLAYABLE` spawn;
  - a cache is only in a nest room, has 2–3 items, and is never on a wall, a rock or a spawn;
  - a brain with `canWake = false` stays idle even close by;
  - the existing reachability test still holds.
- [ ] **Step 2: Run the tests.** Expected: FAIL.
- [ ] **Step 3: Implement.** Keep a seed fully deterministic.
- [ ] **Step 4: Run** `npm test`. Expected: all pass.
- [ ] **Step 5: Commit** «Grotta: rolige rom, reir, sperret trapperom og flaggermus».

### Task 3: Rommene i scenen

**Files:** `src/game/cave/CaveScene.ts`, `src/game/bridge.ts`.

**Interfaces:**
- **Consumes:** task 2.
- **Bridge:**
  - `WorldState.cave` gains `stairsLocked: boolean`;
  - new `Zone` `"caveCache"`;
  - new event `cacheOpened: void` (HUD → scene).
- **Waking:** each brain gets `canWake = roomAt(knight) === spawn.room`.
- **Flying:** bats use a `move` that collides with walls only.
- **Locked stairs:**
  - While `floor.locked` and a live monster is in `stairsRoom`, the stairs zone gives no `"caveStairs"` and `stairsLocked` is true.
  - The stairs get a dark tint, and the marker light is off.
  - When the last one in the room falls, `stairsLocked` turns false and a short light pulse plays on the stairs.
- **Nest cache:**
  - A closed chest (`dungeon` 89) at `cache`. Within 24 px the zone is `"caveCache"`.
  - On `cacheOpened`, it switches to the open frame. Check 89–91 visually.
  - It emits `found` for each item and shows `floatText` «+N Navn».
  - It opens once per floor.

### Task 4: Isvetten, kista og hvileplassen

**Files:** `src/game/cave/CaveScene.ts`, `src/game/bridge.ts`, `src/components/GameClient.tsx`.

**Interfaces:**
- **`WorldState`:**
  - gains `defeatedBosses: string[]` and `openedChests: string[]`, which `GameClient` pushes from `progress`;
  - `cave` gains `boss: { name: string; hp: number; maxHp: number } | null`.
- **Events:**
  - `bossDefeated: EnemyId`;
  - `chestOpened: string`;
  - `restReached: number` (the depth).
  - `Zone` gets `"caveChest"`.
- **Isvetten** (`yeti`). On rest floors the scene draws `yeti` spawns even though bosses are not in `PLAYABLE`. `drake` (floor 10) is still not drawn; that is G4.
  - it is drawn only when not in `defeatedBosses`;
  - it uses `scaleEnemy("yeti", 5)` and its charge;
  - at half hp, once, two rats are spawned next to it with `canWake = true`;
  - `cave.boss` follows its hp.
  - When it falls, the scene emits only `bossDefeated("yeti")`, never `enemyDefeated`. React writes `bosses.yeti`, and its XP is counted from that fact (task 1). The two summoned rats give normal XP through `enemyDefeated`.
- **The chest:**
  - The zone `"caveChest"` is active only when the boss is gone. Its prompt is «<kbd>E</kbd> Åpne kista».
  - `chestOpened(id)`: React writes `chests[id]` and shows the toast `{ title: "Rustning", body: "Du fant den i kista på etasje 5." }`.
  - An opened chest is drawn open and gives nothing more.
- **Rest floor:**
  - The first time you reach a rest floor on a trip: `hp = max`, and the scene sends `restReached(depth)`. React runs `secureTrip`.
  - The rope already exists from G1.
