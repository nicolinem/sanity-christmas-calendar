# Grotta: G4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Etasje 6–10 blir ferdige. Det betyr:
- troll og kyklop;
- isklumper som kastes og kan unngås;
- Isdragen og kista på etasje 10;
- etasje 10 som bunn inntil videre.

**Architecture:**
- Kasting er ren logikk.
  - `brain.ts` får et skudd-steg: holde avstand, sikte (et varsel) og kaste.
  - `stepBrain` returnerer et `shot`.
  - Isklumpen er en ren `Projectile` med `stepProjectile` i `cave/projectiles.ts`.
- Scenen tegner varsler og isklumper, styrer dem på scenens egen `clock` og bruker de samme treff-reglene som bitt og storming.
- Isdragen bruker sjefsveien fra G3 (`boss`, `bossDefeated`, sjefens liv) og kista fra G3 (`chestOpen` / `chestOpened`).

**Tech Stack:** Phaser 4.2.1, React 19 / Next 16, TypeScript, `node --test` med `sucrase`.

**Spec:** `docs/plan-grotta.md`:
- del 14 («G4: beslutninger»);
- del 5 (kamp, varsler);
- del 8 (tall);
- del 13 (sjef og kiste).

Bygger på grenen `claude/grotta-g3` (PR 38).

## Global Constraints

- Alt står bak `FEATURES.cave`. Med flagget av er bygda nøyaktig som før.
- Alle angrep varsles. En kyklop løfter seg og blinker før kastet. Isklumpen er stor (16 px) og treg (startverdi 60 px/s mot spillerens 64).
- Grotta står stille når den holdes (`held`): ingen isklumper beveger seg, og ingen tidtakere går. Alt bruker scenens `clock`.
- Høyst 3 isklumper i lufta per etasje. Ingen nye objekter per bilde utover det å lage en isklump.
- Fakta gir XP og utstyr én gang: `bosses.drake` og `chests["cave-10"]`.
- Norsk tekst nøyaktig:
  - «Isdragen»;
  - «Lenger ned er det ikke gravd ennå.»;
  - toasten `{ title: "Kista på etasje 10", body: "Den var full av gamle notater. Du fikk 100 XP." }`.
- Bare Kenney-ark i repoet. Isdragen er `dungeon` 110 med blå `setTint`. Ingen nye avhengigheter.
- Kjør `npx prettier --write` på endrede filer. Commit aldri `.claude/launch.json` eller `docs/presentasjon/`.

### Task 1: Kasting som ren logikk, og balanse

**Files:** `src/game/cave/enemies.ts`, `combat.ts`, `brain.ts`, and `projectiles.ts` (new). Tests: `combat.test.cjs`, `brain.test.cjs`, `projectiles.test.cjs` (new).

**Interfaces:**
- **Constants in `combat.ts`:**

  | Constant | Value |
  | --- | --- |
  | `KEEP_MIN` | 64 |
  | `KEEP_MAX` | 112 |
  | `SHOOT_RANGE` | 160 |
  | `AIM_MS` | 600 (scaled like windup, never below `MIN_WINDUP_MS`) |
  | `SHOT_REST_MS` | 400 |
  | `PROJECTILE_SPEED` | 60 |
  | `PROJECTILE_HIT` | 10 |
  | `PROJECTILE_RANGE` | 240 |
  | `MAX_PROJECTILES` | 3 |

  `scaleEnemy` also returns `aimMs: number | null` and `everyMs: number | null` (from the first `shoot` move).
- **`Brain`:**
  - `mode` gains `"aim"`;
  - new fields `nextShotAt: number` (0 = may shoot at once) and `aimDir: Point`.
- **`stepBrain(...)` returns `{ brain, strike, shot?: { x: number; y: number; dir: Point; damage: number } }`.**
  - **Pure shooter (cyclops), once awake:**
    - distance < `KEEP_MIN` → move away;
    - distance > `KEEP_MAX` → move closer;
    - otherwise stand still.
    - When `now ≥ nextShotAt` and distance ≤ `SHOOT_RANGE`: `aim` until `now + aimMs`, with `aimDir` locked toward the player. Then `shot` from its own position along `aimDir`, `rest` for `SHOT_REST_MS`, and `nextShotAt = now + everyMs`.
  - **Charge + shoot (drake):** if distance < `CHARGE_TRIGGER` and not resting, charge as today. Otherwise, if a shot is ready, aim and shoot. Otherwise chase.
  - **`canWake = false`** keeps an idle shooter idle: no aim and no shot.
- **`projectiles.ts`:**
  - `type Projectile = { x: number; y: number; dir: Point; damage: number; travelled: number; alive: boolean }`;
  - `spawnProjectile(shot): Projectile`;
  - `stepProjectile(p, dtSec, blocked: (x: number, y: number) => boolean, player: Point): { p: Projectile; hit: number }`.
    - It moves `PROJECTILE_SPEED × dt` along `dir`.
    - It dies when `blocked` is true at the new point, when `travelled > PROJECTILE_RANGE`, or when it hits the player (within `PROJECTILE_HIT`). A hit gives `hit = damage`.
    - `dt = 0` changes nothing.
- **Balance in `enemies.ts`:**
  - `troll.damage = 2` and `drake.damage = 2`;
  - `PLAYABLE` gets `"troll"` and `"cyclops"`;
  - the bosses stay outside `PLAYABLE`.

### Task 2: Troll, kyklop og isklumper i scenen

**Files:** `src/game/cave/CaveScene.ts`.

**Interfaces:**
- **Consumes:** task 1.
- **Monster drawing:** troll and cyclops are drawn because they are now in `PLAYABLE`.
- **Aim tell:** while a brain is in `aim`, its sprite lifts 3 px and flashes white, unlit, as the white tells in G3 do.
- **Isklumper:**
  - A `shot` makes an isklump (`dungeon` 56, lit) unless `MAX_PROJECTILES` are already flying, in which case the shot is skipped.
  - Each frame, when not held, `stepProjectile` runs with `dt` from the scene's clamped delta. `blocked` checks walls and remaining rock boxes.
  - A `hit` uses the same rules as a bite: invulnerability, `caveGod`, knockback, faint.
  - Dead isklumper are destroyed. All of them are destroyed in `buildFloor` and on teardown.
- **Held:** while `held`, isklumper don't move, and the aim timers stand still (`clock`).
