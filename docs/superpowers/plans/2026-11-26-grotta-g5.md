# Grotta: G5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Materialene fra grotta brukes til å smi utstyr til figuren. Det betyr:
- to oppskrifter, fra kistene på etasje 5 og 10;
- typene `recipe` og `forging` i Studio;
- materialer som trekkes i spillet;
- «Mangler 2 Isskår» til de er samlet.

**Architecture:**
- Oppskriftene og reglene er ren logikk uten React, Phaser og Sanity:
  - `src/game/recipes.ts` har data;
  - `src/game/forge.ts` har `applyForgings` og `recipeStates`.
- Utstyret regnes ut av `crafted` i `ownedGear`, slik kistene og sideoppdragene gjør i dag.
- Studio får to ferdige typer i `src/sanity/schemaTypes/forge.ts`, registrert i `index.ts` når `FEATURES.cave` er på. Spillerens filer (`item.tsx` og `sanity.config.ts`) røres ikke.
- `/api/forge` leser publiserte Smiinger og legger inn oppskriftene, på samme måte som `/api/archive`.
- `GameClient` henter Smiingene i `refresh`, kjører `applyForgings` når de eller `inventory` endrer seg, og viser en toast per ny ting.

**Tech Stack:** Next 16 App Router, React 19, Sanity Studio (embedded på `/studio`), TypeScript, `node --test` med `sucrase`.

**Spec:** `docs/plan-grotta.md`, del 15 («G5: smiing»). Bakgrunnen står i `docs/plan-utforsking.md`, «Smiing».

Bygger på grenen `claude/grotta-g4` (PR 39).

## Global Constraints

- Alt står bak `FEATURES.cave`. Med flagget av finnes ingen nye typer i Studio, ingen kall til `/api/forge` og ingen Smia i Ting.
- **Spillerens filer røres ikke:** `src/sanity/schemaTypes/item.tsx` og `sanity.config.ts`. `schemaTypes/index.ts` får de nye typene, slik uke 2 gjorde.
- Studio-filer bruker relative importer, ikke `@/`, fordi Sanity CLI bundler uten aliaset.
- Oppskriftene, nøyaktig:
  - `recipe-isskjold`: «Isskjold», fra `chests["cave-5"]`, gir `extra:shield`, Gammel malm × 4 og Isskår × 2;
  - `recipe-ishjelm`: «Ishjelm», fra `chests["cave-10"]`, gir `hat:icehelm`, Gammel malm × 6 og Isskår × 4.
- Det er koden (`RECIPES`) som avgjør hva som trekkes. Dokumentet i Sanity brukes bare for `_id`.
- Bare `inventory` teller. `trip` teller ikke.
- Hver oppskrift gir utstyret én gang. Hver Smiing (`_id`) brukes én gang.
- Norsk tekst, nøyaktig:
  - kilder: «Oppskrift fra etasje 5» og «Oppskrift fra etasje 10»;
  - toast for kista på etasje 5: `{ title: "Rustning og en oppskrift", body: "Kista på etasje 5 hadde rustning og oppskriften på et isskjold." }`;
  - toast for kista på etasje 10: `{ title: "Kista på etasje 10", body: "Den var full av gamle notater, og ett var oppskriften på en ishjelm. Du fikk 100 XP." }`;
  - Smia-linjer: «Smidd», «Mangler 2 Isskår» (to materialer: «Mangler 3 Gammel malm og 2 Isskår») og «Lag en Smiing i Studio»;
  - materialene: «Kald og klar. Brukes i smia.» og «Tung og rusten. Brukes i smia.»
- Studio-typene har norske titler: «Oppskrift», «Smiing», «Navn», «Oppskrift», «Gir», «Ingredienser», «Materiale», «Antall» og «Beskrivelse».
- Utstyret tegnes som de andre delene i `figure.ts`, med Kenneys palett. Ingen nye bildefiler og ingen nye avhengigheter.
- Kjør `npx prettier --write` på endrede filer. Commit aldri `.claude/launch.json`, `docs/presentasjon/` eller `.playwright-mcp/`.
- Nettlesersjekken skriver ikke til brukerens Sanity-prosjekt. Den bruker `page.route` mot `/api/forge`.

## Review Focus

1. **Ikke nok materialer:** ingenting trekkes, ingenting settes i `crafted`, og Smia viser «Mangler …». Når materialene kommer i `inventory`, smis den av seg selv. Testes i task 1. I task 3 testes at effekten kjører igjen når `inventory` endrer seg.
2. **Samme oppskrift to ganger:** to publiserte Smiinger av Isskjold og materialer nok til begge. Bare den første trekker. Den andre gir ingenting. Testes i task 1.
3. **Oppskrift som ikke er låst opp:** en Smiing som peker på `recipe-ishjelm` uten `chests["cave-10"]` trekker ingenting. Den smis når kista åpnes. Testes i task 1.
4. **Smiing med ukjent eller tom `recipe`:** den hoppes over uten feil, både i `applyForgings` og i ruta. Testes i task 1 og 2.
5. **Lagret post med søppel i `crafted`:** tall, null og lister vaskes bort i `readProgress`, og `ownedGear` overser ukjente oppskrifts-id-er. Testes i task 1.

### Task 1: Oppskrifter, smiing og utstyr som ren logikk

**Files:**
- Create: `src/game/recipes.ts`, `src/game/forge.ts`, `src/game/forge.test.cjs`
- Modify: `src/game/quests/types.ts`, `src/game/quests/progress.ts`, `src/game/figure.ts`, `src/game/wardrobe.ts`, `src/game/materials.ts`, `src/game/cave/chests.ts`
- Test: `src/game/forge.test.cjs`, `src/game/wardrobe.test.cjs`, `src/game/quests/progress.test.cjs`

**Interfaces:**
- Produces:
  - `type RecipeId = "recipe-isskjold" | "recipe-ishjelm"`.
  - `type Recipe = { id: RecipeId; name: string; chest: string; gear: GearKey; ingredients: { material: MaterialId; count: number }[]; description: string }`.
  - `RECIPES: Record<RecipeId, Recipe>`, `RECIPE_IDS: RecipeId[]` (etasje 5 først), `isRecipeId(id: unknown): id is RecipeId` og `unlockedRecipes(p: Partial<Pick<Progress, "chests">>): RecipeId[]`.
  - `type Forging = { _id: string; name: string; recipe: string | null }`.
  - `missingFor(inventory: Record<string, number>, id: RecipeId): { material: MaterialId; count: number }[]`, i oppskriftens rekkefølge, bare det som mangler.
  - `missingText(missing): string`, for eksempel «Mangler 2 Isskår». Tom liste gir `""`.
  - `applyForgings(p: Progress, forgings: Forging[]): { progress: Progress; forged: { forging: Forging; recipe: RecipeId }[] }`. Smiingene behandles i rekkefølgen de kommer. Når ingenting smis, er `progress === p`.
  - `type RecipeState = { id: RecipeId; state: "done" | "missing" | "todo"; missing: { material: MaterialId; count: number }[] }`.
  - `recipeStates(p: Progress, forgings: Forging[]): RecipeState[]`, bare for låst opp oppskrifter. `"missing"` betyr at en publisert Smiing finnes og noe mangler.
  - `Progress.crafted: Record<string, string>` (Smiingens `_id` → oppskriftens id).
  - Gear: `extra:shield` («Isskjold», `unlock: RECIPE_5_SOURCE`) og `hat:icehelm` («Ishjelm», `unlock: RECIPE_10_SOURCE`). `RECIPE_5_SOURCE = "Oppskrift fra etasje 5"` og `RECIPE_10_SOURCE = "Oppskrift fra etasje 10"` eksporteres fra `figure.ts`.

### Task 2: Oppskrift og Smiing i Studio, og `/api/forge`

**Files:**
- Create: `src/sanity/schemaTypes/forge.ts`, `src/app/api/forge/route.ts`, `src/game/forgeRoute.test.cjs`
- Modify: `src/sanity/schemaTypes/index.ts`, `src/sanity/lib/solved.tsx`, `src/components/hud/useLive.ts`

**Interfaces:**
- Consumes: `RECIPES`, `RECIPE_IDS`, `unlockedRecipes` and `isRecipeId` from Task 1 (`../../game/recipes`).
- Produces:
  - Schema type `recipe`:
    - `name` (string), `gear` (string), `description` (text);
    - `ingredients`: an `array` of objects `{ material: string (list: isskar / malm, with the material names as titles), count: number }`;
    - the whole document `readOnly: true`.
  - Schema type `forging`:
    - `name` (string, required);
    - `recipe` (`reference` to `recipe`, required), with `options: { filter: () => ({ filter: "_id in $ids", params: { ids: unlockedRecipeIds() } }), disableNew: true }` and `description: "Bare oppskrifter du har funnet i grotta."`;
    - preview: title `name`, subtitle `recipe.name`.
  - `unlockedRecipeIds(): string[]` in `solved.tsx`: `unlockedRecipes({ chests })` from the same stored record, `[]` without a browser or storage.
  - `GET /api/forge` → `{ configured: boolean; forgings: Forging[]; recipes: string[] }`:
    - `forgings` are published `forging` documents ordered by `_createdAt asc`, from `{_id, name, "recipe": recipe._ref}`;
    - `recipes` are the `_id`s of `recipe` documents that exist;
    - on an error: `{ configured: true, forgings: [], recipes: [], error: "fetch_failed" }`.
  - `POST /api/forge` → `createIfNotExists` for every recipe in `RECIPES`, with `_id` = the recipe id and the fields above. It has the same origin and token checks as `/api/archive` (403 `invalid_origin`, 503 `no_token`).

- [ ] **Step 1: Write the failing test**

`src/game/forgeRoute.test.cjs` runs the route in `vm` the same way `archiveRoute.test.cjs` does, with `@/game/recipes` as the real module. It checks:
- POST from the same origin creates exactly 2 documents with `_id` `recipe-isskjold` and `recipe-ishjelm`, `_type: "recipe"`, and `ingredients` with `_key`, `material` and `count` (malm 4, isskar 2 for the shield).
- POST from another origin gives 403. POST without a token gives 503.
- GET without a client gives `{ configured: false, forgings: [], recipes: [] }`.
- GET where the client's `fetch` returns a forging with `recipe: null` passes it on unchanged. Skipping it is the game's job.

### Task 3: Forging in the game and the Smia in Ting

- [ ] **Step 1: Fetch in `refresh`**

Only with `FEATURES.cave`, `fetch("/api/forge")` runs in the same `Promise.all`. It produces `forgings: Forging[] | null` (`null` on an error) and `recipeDocs: string[] | null`.

- [ ] **Step 2: Seed the recipes**

Use the same pattern as `archiveSeeded`:
- When `recipeDocs !== null` and an id from `unlockedRecipes(progress)` is missing from it, POST once per visit.
- Call `markOwnWrite()` first, and `refresh()` when the response is ok.

- [ ] **Step 3: Forge**

An effect runs on `forgings` and `progress.inventory`, `progress.chests` and `progress.crafted`:
- `updateProgress(project, (p) => applyForgings(p, forgings ?? []).progress)`;
- one toast per forged thing: `{ title: RECIPES[recipe].name, body: "«<forging.name>» er klar. Du finner den under Utstyr.", tone: "forge" }`.

It must not forge twice when the effect runs again. `crafted` stops that, so read `forged` from the same call that updates. The new gear gets the «Ny» mark through `seenGear` as it does today.

- [ ] **Step 4: Smia in Ting**

In `mode === "bag"` there is a section «Smia» above «Fra grotta», only with `FEATURES.cave` and at least one unlocked recipe. It has one row per `recipeStates(...)`:
- the recipe's name;
- the ingredients as «Gammel malm 3/4 · Isskår 2/2», with the material sprite;
- one line: «Smidd» / `missingText(missing)` / «Lag en Smiing i Studio».

A `"missing"` row is greyed out. CharacterSheet gets `forgings` as a prop from GameClient. The styling uses the classes `.cs-found` already has.
